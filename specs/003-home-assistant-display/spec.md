# Feature Specification: Home Assistant Paper Display — Layout B

**Feature ID**: `003-home-assistant-display`

**Status**: デザイン確定・実装未着手

## 目的と範囲

800×480の6色e-inkに、Star / Moonの予定、Living / Study / Bedroom / Outdoorの温湿度、3時間刻みの天気予報を表示する。HAが専用画像を生成し、ESP32が起床時に取得・検証・保存・表示する。HAから通信状態と最後に表示した画面を確認できる。

画面はLayout Bで固定する。上部に日付と更新情報、左にStar / Moonのカレンダー、右にRoomsとForecastを配置する。Star / Moonは24px、予定ブロック間の見える余白は約38px、RoomsからForecastは約36px。書体はIBM Plex Sans / Mono、日本語はNoto Sans JP。英語UIと予定の原文を使用する。

対象は表示と表示デバイスの管理。電力、買い物、写真、家電操作、施解錠、カメラ配信は含めない。HA統合・ファームウェア・実機受入は実装タスクとして管理する。

## User Scenarios & Testing

### US1 — 2人の予定と家の状態を確認する（P1）

利用者は日付、Star / Moonそれぞれの予定、部屋別温湿度、3時間刻みの天気予報を確認できる。

**Independent Test**: 2人分のcalendar fixtureと実HAの温湿度/時間別予報を採用画面に表示する。

1. **Given** 2人の予定がある、**When** 更新する、**Then** 白黒のMDI所有者アイコンがある独立した2領域にそれぞれ最大3件を表示する。
2. **Given** 一人に4件以上ある、**When** 表示する、**Then** 超過はその人のアイコン見出しの右に`+N more`と表示し、もう一人の領域を減らさない。
3. **Given** 一人の取得に失敗する、**When** 更新する、**Then** その人は`Unavailable`、もう一人と温湿度/予報は正常に更新する。取得成功の空は`No events today`、未設定は`Calendar not linked`と区別する。
4. **Given** 時間別予報が取得できる、**When** 13:30に生成する、**Then** 15:00 / 18:00 / 21:00 / 翌00:00の4枠に天候と気温を表示する。欠損時刻は`—`とし、別時刻や現在の天気で補わない。

### US2 — 英語主体の画面を色で読み分ける（P1）

英語の見出しと簡潔な数値を読みやすくし、日本語の予定も欠けずに表示する。

**Independent Test**: 色票、英語/日本語の長い予定、同時刻の2人の予定を実機で確認する。

1. **Given** StarとMoonの予定、**When** 表示する、**Then** 1人目Starと2人目MoonはStar / Moonの形で識別できる。個人ごとの縦帯は使わない。
2. **Given** 英語UIで日本語の予定、**When** 組版する、**Then** 原文を保ち、文字幅で1行に省略する。翻訳やローマ字化を行わない。
3. **Given** 6色色票、**When** 描画、**Then** 色コードが対応し、文字/罫線は単色で明瞭に表示する。

### US3 — 通信がなくても意味のある画面を残す（P1）

ネットワーク断、HA停止、電源再投入でも、最後の有効情報とその鮮度を確認できる。

**Why**: 画面が無通電でも残るe-inkでは古い情報を現在値に見せないことが必要。

**Independent Test**: 正常表示後にネットワーク断と電源断を注入する。

1. **Given** 有効な保存フレーム、**When** 次回取得失敗、**Then** 同じ情報を保持し、可能な場合は予約済み上部状態欄に通信断と最終取得日時を付ける。
2. **Given** チェックサム不一致/未対応形式、**When** フレームを受信、**Then** 現在画面と正常キャッシュを置き換えない。
3. **Given** 画面書換途中で電源断、**When** 再起動、**Then** 有効キャッシュを全画面再表示して回復する。断電中の画面が完全であることは保証しない。
4. **Given** 時計不明、**When** 起動、**Then** 鮮度を現在時刻で偽装せず`Time not synced`扱いにする。

### US4 — HAから端末の状態を確認する（P1）

利用者はHAのデバイスページで通信・電池・最終表示・更新待ちを確認する。

**Why**: 情報を読むだけでなく、HA管理下の表示デバイスとして成立させる。

**Independent Test**: 端末シミュレータの取得/表示ACKでHA entityを更新する。

1. **Given** 端末が定期スリープ、**When** 次の予定起床前、**Then** 異常なオフラインとせず「スリープ予定」扱いにする。
2. **Given** HAで再生成を要求、**When** 端末がスリープ中、**Then** 「次回接続で反映」と示し、即座に画面が変わったとは報告しない。
3. **Given** 新画像を生成済み、**When** ACK未受信、**Then** 配信予定画像と最後に端末が表示成功を報告した画像を区別する。

## Requirements

### 表示

- **FR-001**: 表示は800×480横向き、6色のネイティブパレットに限定する。本文・罫線・アイコンを単色で描画する。
- **FR-002**: 予定タイトル24px、所有者のMDIアイコン24px、補助情報16px以上、温度34px、予報気温24px・時刻16px・アイコン32px、罫線2px以上を基準にする。白地に黄色の本文を置かない。
- **FR-003**: Layout Bとして、日付、Star / Moonの固定2領域（各最大3件）、3部屋＋屋外の温湿度、3時間刻みの予報4枠、固定上部状態欄を表示する。買い物・瞬時電力・プラグ別電力・積算・料金・掃除機・アートは画面に含めない。詳細はselected-layout.mdに従う。
- **FR-004**: 未設定、取得不可、古い値、正常なゼロ/空を区別する。空きを埋めるために架空のentity/値/予定を表示しない。
- **FR-005**: 天気は`weather.wu_wai_forecast_home`を初期割当候補に、`weather.get_forecasts`のhourlyを取得する。予報日時を表示TZへ変換し、生成時刻以上の最初の3時間境界から4枠を選ぶ。気温は°Cへ正規化し整数で表示する。温湿度の°C/% RHも明示する。元の数値/単位と表示の丸めを分離する。
- **FR-006**: 「現在時刻」のような連続時計を置かず、共通上部状態欄に取得日時・次回予定を示し、異常時は各情報の鮮度を示す。予報の有効時刻を各列に表示する。取得元名や`As of`は不要。上部状態欄の日付にもカンマを使わない。
- **FR-007**: 固定見出し・部屋名・日付・状態表示は英語を既定とし、予定タイトルは原文の言語を維持する。書体はIBM Plex Sans / Mono、日本語はNoto Sans JP。画面の所有者は白黒のMDIアイコンで示し、内部設定とアクセシブル名もStar / Moonとし、個人名は保存しない。

### HA連携・構成

- **FR-008**: HA設定でStarとMoonに各1つのcalendar entity、温湿度4組、hourly対応weather entity 1つを割り当てられる。個人名/HA person entityから予定所有者を推測しない。実entity IDをファームウェアへ固定しない。
- **FR-009**: HA側がデータ集約、英語/日本語組版、MDIアイコンのラスタライズ、6色フレーム生成を担当し、端末は取得・検証・保存・全画面更新・スリープを担当する。
- **FR-010**: 端末をHAデバイスとして登録し、最終接続、最終表示成功、電池残量（取得不可ならunknown）、RSSI、ファームウェア版、次回予定、エラー、更新待ち、画像プレビューを提供する。
- **FR-011**: HA操作は画像再生成と表示間隔設定に限定する。スリープ端末の遠隔即時起床を約束しない。家電制御、施解錠、カメラ配信は対象外。
- **FR-012**: HA標準のHome画面をスクリーンショット化せず、データからe-ink専用画面を組み立てる。
- **FR-013**: 実装初期はHA 2026.9.1を検証対象とし、他バージョンの動作保証は確認後に追加する。既存モードは設定で選択可能とし、自動的に別情報源へ切り替えない。

### 更新・耐障害性

- **FR-014**: 電池運用の初期値は06:00–22:00が30分、22:00–06:00が120分。05:59等の境界は次の06:00を越えて寝ない。日付変更でも日付の更新を予約する。初期設定はJST。
- **FR-015**: 連続全画面更新の下限は暫定300秒とし、要求をまとめて最新1枚を表示する。電源再投入時の回復表示は例外。パネル実測後に範囲を確定する。
- **FR-016**: 同じ配信フレームを再取得しても再描画しない。画面の取得時刻/日付/鮮度が変わる定期更新は別フレームになり得る。重複省略による電池寿命を未計測で約束しない。
- **FR-017**: 個別データの失敗はその領域だけへ反映する。片方のcalendarや温湿度が欠落しても全画面をエラー画面にしない。
- **FR-018**: フレーム長・寸法・バージョン・パレット・SHA-256・各ピクセル値を検証してから表示する。保存はA/B世代で行い、途中失敗で前の正常フレームを失わない。
- **FR-019**: 通信、BUSY待ち、SPI転送に有限の期限を設け、失敗を上位へ返す。表示成功ACKは全画面更新完了後にだけ送る。
- **FR-020**: 初回未設定/キャッシュなしでは端末内の案内画面を表示する。認証エラーを無限再試行しない。

### 認証・データ

- **FR-021**: 調査用のHAトークンを製品やリポジトリに保存しない。端末は端末専用キーを使用し、配信/自身の状態報告にのみ権限を限定する。認証なしの画像配信やクエリ文字列の秘密値を禁止する。
- **FR-022**: HTTPSの証明書検証を実装する。現環境のHTTPを利用する場合は端末専用キーに限定した明示設定とする。HTTPは暗号化されないことをセットアップに記載する。
- **FR-023**: 画像の外部URL自由入力と買い物リストの取得/設定/表示はMVPに含めない。機密値や実際の予定をログ/テストfixtureへ複製しない。

### カレンダー

- **FR-024**: 当日の終日予定、進行中、今後の予定を所有者ごとに取得し、終日→進行中→開始時刻順で各3件を表示する。終了済みは除く。終日は`All day`、進行中は`Now`。日付境界/終了時刻は排他的に扱う。
- **FR-025**: 一人の余った表示枠をもう一人へ再配分しない。共有予定も両所有者に属するなら双方に表示する。多件数は`+N more`で示す。
- **FR-026**: 予定の取得失敗/未設定/成功0件を所有者別に区別し、キャッシュ表示時は`Stale`を添える。古い予定を今日の予定へ日付だけ付け替えない。

- **FR-027**: 所有者マークはHome AssistantのMDIを使い、HA側で黒白2値へラスタライズする。版/ハッシュ/ライセンスと予備マスクを固定する。所有者はStar=`mdi:star-four-points`、Moon=`mdi:moon-waning-crescent`、ともに24pxで固定する。端末の絵文字フォントに依存しない。

### 天気予報

- **FR-028**: 予報4枠は00/03/06/09/12/15/18/21時に対応する時刻・天候アイコン・気温で構成し、翌日には`+1d`を添える。3時間刻みと画面更新間隔を混同しない。日次予報、現在state、補間値から時間別予報を作らない。詳細は[forecast.md](forecast.md)。
- **FR-029**: 予報の未設定、hourly非対応、取得失敗、個別欠損、古いキャッシュを区別する。失敗時に有効な前回予報を使うなら即`Stale`、最終成功から6時間以上なら値を隠す。キャッシュの有効日時を変更しない。温湿度とカレンダーは独立して更新する。
- **FR-030**: weather用字形も版固定のMDIでHA側ラスタライズする。色と形で天候を示し、未知conditionは`?`、欠損は`—`とする。Powerと買い物のentity設定/取得/描画をMVPに含めない。

- **FR-031**: 日付を左、更新情報を右の上部バーに配置する。Homeタイトルと下端情報欄は置かない。状態overlayはx=344/y=24/w=432/h=40。3セクションの見出しは高さ20px＋下余白12pxで統一し、文字のみを表示する。Starの最終予定行からMoonアイコンまで約38px、Roomsの最終数値行からForecast見出しまで約36pxを確保する。寸法はselected-layout.mdに従う。

### Key Entities

`DisplayConfig`（entity割当と更新設定）、`DisplaySnapshot`（正規化された値と鮮度）、`RenderedFrame`（検証可能な画像）、`DeviceReport`（実際に表示した世代と端末状態）。詳細は[data-model.md](data-model.md)。

### Edge Cases

entityの削除/リネーム、`unknown`/`unavailable`、予定の重複/順序逆転、日付跨ぎ、単位差、通信途中切断、JSON過大、フレーム過大、SHA不一致、未定義色、RTC消失、サーバー再起動、表示ACK欠落、描画途中断電、日本語の長文/欠落グリフ、電池測定不可を検証対象とする。2人同時刻、片方未設定、片方取得失敗、終日・TZ・終了時刻排他・複数日イベントも検証する。予報は3時間境界、UTC→JST変換、翌日表示、順序逆転/重複/欠損、hourly非対応、未知condition、欠落字形、°F→°C、負の気温、キャッシュ失効を検証する。

## Success Criteria

- **SC-001**: 初期設定後、対象HAの温湿度/時間別予報と設定した2人分のcalendarで採用画面を表示し、画面の値/単位が取得時点の値と一致する。
- **SC-002**: 実機1m・通常の室内照明で、日付・予定の所有者・主要数値を5秒以内に読み取れる。英語/日本語の予定が欠けず、色票6色が対応する。
- **SC-003**: ネットワーク断、破損画像、HA停止、ACK欠落、時計未同期、断電復旧の各試験で、誤った成功報告や正常キャッシュの消失がない。
- **SC-004**: 30分/120分更新と日付/昼夜境界が仕様どおりで、同一フレームの再ポーリングではパネルを更新しない。
- **SC-005**: HAのデバイスページで更新要求から表示ACKまで追跡できる。未応答端末を次回予定＋10分以内に「接続遅延」と判定する。
- **SC-006**: 有効ネットワークと正常パネルで起床からスリープまで120秒以内を目標とし、実機で時間・ピークメモリ・1更新の消費電力量を記録する。連続電池駆動日数は測定から算出する。

## 実装前の確認事項

Star / Moonのcalendar entityと連携元、実パネル型番/色コード、物理フラッシュ容量、電池残量APIの精度を確認する。画面デザインと表示内容は確定済み。性能・消費電力・距離での可読性は実機で検証する。
