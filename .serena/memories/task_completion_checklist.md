# タスク完了時のチェックリスト

## コード作成・変更後

### 1. コードレビュー
- [ ] 命名規約に従っているか確認
- [ ] コメントが適切に記載されているか確認
- [ ] エラーハンドリングが実装されているか確認
- [ ] メモリリークの可能性がないか確認
- [ ] NULLポインタチェックが適切か確認
- [ ] バッファオーバーフローの可能性がないか確認

### 2. ビルド確認
```powershell
# ビルドエラーがないか確認
idf.py build
```

### 3. サイズ確認
```powershell
# バイナリサイズが制限内か確認
idf.py size
idf.py size-components
```

### 4. 警告確認
- [ ] ビルド時の警告がゼロか確認
- [ ] 未使用変数・関数がないか確認

## 機能実装完了後

### 1. 単体テスト
- [ ] 新規関数の基本動作確認
- [ ] エッジケース(境界値)のテスト
- [ ] エラーケースのテスト
- [ ] メモリ使用量の確認

### 2. 統合テスト
- [ ] 他のコンポーネントとの連携確認
- [ ] ハードウェアとの動作確認
- [ ] タイミング・シーケンスの確認

### 3. 実機テスト
```powershell
# フラッシュ書き込み + モニター起動
idf.py -p COM4 flash monitor
```

実機テストで確認すべき項目:
- [ ] 正常動作するか
- [ ] エラーログが出ていないか
- [ ] メモリ使用量が適切か(`esp_get_free_heap_size()`)
- [ ] タイミングが適切か(ディスプレイリフレッシュ等)

### 4. メモリ確認
ログで以下を確認:
- [ ] ヒープメモリの残量
- [ ] PSRAMの使用状況
- [ ] スタックオーバーフローが発生していないか

### 5. 電力消費確認(該当する場合)
- [ ] ディープスリープに正常に入るか
- [ ] 起動時間が適切か
- [ ] 消費電流が想定内か

## ドキュメント更新

### 1. コメント・ドキュメント
- [ ] 関数ドキュメント(Doxygen形式)が記載されているか
- [ ] 複雑なロジックに説明コメントがあるか
- [ ] TODOコメントが残っていないか(または意図的に残すか明記)

### 2. README/実装計画書更新
- [ ] IMPLEMENTATION_PLAN.mdのチェックリストを更新
- [ ] 新規追加した機能をドキュメント化
- [ ] 既知の問題・制約事項を記載

## Git操作

### 1. コミット前
```powershell
# 変更内容確認
git status
git diff

# 不要なファイルが含まれていないか確認
# (ビルド成果物、一時ファイル等)
```

### 2. コミットメッセージ
良いコミットメッセージの例:
```
[component] 簡潔な変更内容の要約(50文字以内)

詳細な説明(必要に応じて):
- 変更理由
- 実装の詳細
- 影響範囲
- テスト結果
```

### 3. コミット
```powershell
git add .
git commit -m "適切なコミットメッセージ"
```

### 4. プッシュ前確認
- [ ] ローカルでビルドが成功しているか
- [ ] テストが全て通っているか
- [ ] 機密情報(API Key等)がコミットされていないか

### 5. プッシュ
```powershell
git push origin main
```

## フェーズ完了時

### 1. マイルストーン確認
- [ ] フェーズの全タスクが完了したか
- [ ] 期待される成果物が揃っているか
- [ ] 次のフェーズへの依存関係が満たされているか

### 2. コードレビュー(チームの場合)
- [ ] プルリクエスト作成
- [ ] コードレビュー依頼
- [ ] 指摘事項の対応

### 3. ドキュメント整理
- [ ] 実装内容を記録
- [ ] 技術的な決定事項を記録
- [ ] ハマったポイント・解決方法を記録

## リリース前(最終チェック)

### 1. 全機能テスト
- [ ] 全ての機能が正常動作するか
- [ ] エラーケースが適切に処理されるか
- [ ] ネットワーク障害時の動作確認
- [ ] 長時間動作の安定性確認

### 2. パフォーマンス確認
- [ ] 起動時間が目標内(30秒以内)か
- [ ] ディスプレイリフレッシュが正常か
- [ ] メモリ使用量が適切か
- [ ] バッテリー寿命が想定内か

### 3. セキュリティ確認
- [ ] API Keyが環境変数/menuconfigから読み込まれているか
- [ ] ハードコードされた認証情報がないか
- [ ] HTTPS通信が正しく動作するか

### 4. ドキュメント最終確認
- [ ] READMEが最新か
- [ ] セットアップ手順が正確か
- [ ] 既知の問題が記載されているか
- [ ] ライセンス情報が正しいか

## 注意事項

### やってはいけないこと
- ❌ ビルドせずにコミット
- ❌ 警告を無視してコミット
- ❌ 実機テストせずにマージ
- ❌ ドキュメント更新を忘れる
- ❌ APIキー等の機密情報をコミット

### 推奨事項
- ✅ 小さく頻繁にコミット
- ✅ 意味のあるコミットメッセージ
- ✅ 定期的なバックアップ
- ✅ ログ出力を活用したデバッグ
- ✅ メモリ使用量の定期的な確認
